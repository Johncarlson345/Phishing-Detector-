Fix training-serving skew in feature engineering

Root cause: model was trained on the PhiUSIIL dataset's precomputed
URL features, but their exact extraction logic was never published
and doesn't match plain character-level computation on raw URLs
(verified: dataset URLLength=31 vs actual len()=32 for the same
URL). Training and inference features didn't match, causing wrong
predictions in production despite ~99.7% validation accuracy.

Changes:

- feature_extraction.py: rewritten as single source of truth,
  computing 12 features directly from the raw URL string instead
  of relying on the dataset's undocumented columns.

- model_trainer.py: builds training features by running the raw
  URL column through feature_extraction.py instead of reading the
  dataset's precomputed columns. Also drops PathLength and
  QueryParameterCount - found they were a dataset artifact (every
  legitimate URL was a bare homepage, PathLength always 0), causing
  the model to learn "has a path = phishing" instead of real
  signal. Accuracy held at ~99.5% after removal.

- lambda_function.py: updated import to match new
  feature_extraction.py (extract_features). No other logic changed.

Verified with a sanity check and simulated Lambda events - training
and inference now agree.
